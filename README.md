# GijirokuStudio v2（議事録スタジオ）

リモート会議を **音声（MP3）＋ 画面スライド（JPEG）＋ 文字起こし** で記録し、統合された **議事録（Markdown）** を生成する Windows 向けデスクトップアプリです。すべてローカルで動作し、会議音声が外部に送信されることはありません。

---

## ✨ 主な機能

- **リアルタイム MP3 録音** — スピーカー（ループバック）・マイクを複数同時録音し ffmpeg で MP3 エンコード
- **スライド自動キャプチャ** — 5秒ごとに画面変化（dHash）を検知し、切り替わった瞬間だけ JPEG で保存。手動キャプチャも可能
- **リアルタイム文字起こし（高負荷モード）** — ローカル AI（faster-whisper）で話しながら文字起こし。録音中の言語切替・自動言語検出にも対応
- **議事録の自動生成（後処理）** — 録音データから高精度文字起こし（faster-whisper）を行い、画像と発言を時系列に並べた Markdown を出力
- **用語辞書（glossary.csv）** — よく使う用語・固有名詞を登録し、文字起こしの誤認識を正しい表記に寄せる

## 📦 セットアップ

```bash
# 1) 仮想環境を作成して依存パッケージをインストール
python -m pipenv --python 3.13     # open_py313.bat と同等
pipenv install                      # Pipfile から一括インストール

# 2) 後処理を faster-whisper で行う場合（推奨・精度重視）
pipenv install faster-whisper
```

> `faster-whisper` をインストールしていない場合は、後処理の文字起こしを従来の `moonshine-voice` に自動フォールバックします（アプリはそのまま動きます）。

主な依存パッケージ（`Pipfile`）: `mss`, `pillow`, `imagehash`, `pyaudiowpatch`, `sounddevice`, `moonshine-voice`, `numpy`, `scipy`, `faster-whisper`

## 🎬 使い方（GUI）

1. **会議名を入力**（録画設定パネル先頭）。省略可。フォルダ名・議事録タイトルに使われます。
2. **対象画面** と **音声デバイス** を選択（音声は Ctrl/Shift+クリックで複数選択可・スピーカーとマイク混在可）。
3. **動作モード** を選択：
   - `軽量（録音のみ）` — 音声＋画像のみ（後処理で一括文字起こし）
   - `高負荷（リアルタイム文字起こし）` — 録音中にリアルタイム文字起こしパネルを表示
4. **▶ 会議記録を開始** を押す。画面が切り替わると自動で JPEG が保存されます。
   - 必要に応じて **📷 手動キャプチャ** で任意タイミングの保存も可能。
5. **■ 記録を停止して保存** を押すと、音声のエンコードと保存が行われます。
6. **📄 議事録を生成（後処理）** で対象フォルダを選ぶと、`meeting_report.md` が生成されます。

### 録画設定の項目
| 項目 | 説明 |
|---|---|
| 会議名 | 記録のタイトル。フォルダ名と議事録タイトルに反映（空欄可） |
| 対象画面 | キャプチャするディスプレイ |
| 音声デバイス | 録音対象（複数選択可） |
| 動作モード | 軽量 / 高負荷（リアルタイム文字起こし） |
| 文字起こし言語 | 日本語 / English / 中文 / 한국어（録音中の切替可） |

## ⚙️ 詳細設定

メニュー **設定 → 設定を開く** で変更可能。`settings.json` に保存されます。

| キー | デフォルト | 説明 |
|---|---|---|
| `dhash_threshold` | `10` | 画面変化の検知感度（小さいほど敏感） |
| `audio_gain` | `2.0` | 音声の増幅度（1.0〜5.0） |
| `jpeg_quality` | `85` | キャプチャ画像のJPEG画質（50〜100） |
| `whisper_model` | `large-v3-turbo` | 後処理の faster-whisper モデル（精度重視） |
| `whisper_device` | `cpu` | `cpu` / `cuda`（NVIDIA GPU） |
| `whisper_compute` | `int8` | CPU=`int8`、CUDA=`float16` など |
| `realtime_whisper_model` | `base` | 高負荷モードのリアルタイム文字起こし用モデル（低遅延重視） |

> GPU（CUDA）環境があれば `whisper_device=cuda` / `whisper_compute=float16` にすると、後処理が大幅に高速化します。

## 📖 用語辞書（glossary.csv）

固有名詞・専門用語・人名の誤認識を正しい表記に寄せるための辞書です。プロジェクト直下の `glossary.csv` を Excel やテキストエディタで編集します。

```csv
正規形,読み,別名1,別名2
開発定例会議,カイハツテイレカイギ,開発定例会,
プロダクト戦略室,プロダクトセンリャクシツ,プロダクト線略室,プロダクト戦略しつ
山田太郎,ヤマダタロウ,,
```

- **1行 ＝ 1用語**：1列目＝正規形（議事録に残したい表記）、2列目＝読み、3列目以降＝別名（誤認識されやすい表記）
- `#` で始まる行・空行は無視されます
- **正規形** は faster-whisper の `initial_prompt`（認識バイアス）に使われ、認識時点で正しい用語に寄ります
- **別名** は後処理で「正規形」へ一括置換（完全一致）されます
- Excel で編集する場合は **CSV (UTF-8)** 形式で保存してください

> 辞書がない場合・空の場合は通常の文字起こしとして動作します（エラーにはなりません）。

## 📁 生成されるファイル

録音ごとに `YYYYMMDD_HHMMSS_<会議名>/`（会議名が空なら `_Meeting`）というフォルダが作られます。

```
20260628_143022_定例会議/
├── audio_main.mp3          # 録音データ（MP3）
├── snapshot_HHMMSS_mmm.jpg # 画面変化検知による自動キャプチャ
├── manual_HHMMSS_mmm.jpg   # 手動キャプチャ
├── metadata.txt            # メタ情報（会議名・開始時刻・音声ソース・言語 など）
├── snapshots.jsonl         # キャプチャのタイミングログ
├── language_segments.jsonl # 言語切替のタイミングログ
├── transcription.txt       # リアルタイム文字起こし（高負荷モード時のみ）
└── meeting_report.md       # 後処理で生成される議事録（画像＋発言の時系列統合）
```

## 🔬 後処理の文字起こしについて

後処理（議事録生成）は **faster-whisper**（Whisper系・語彙バイアス対応）で行います。

- 用語辞書から `initial_prompt` を生成し、認識時に正しい用語へバイアスをかけます
- VAD（無音区間除去）を有効化し、会議音声に最適化しています
- 録音中の言語切替がある場合は、区間ごとに言語を指定して文字起こしします
- faster-whisper 未導入時は **moonshine-voice に自動フォールバック** します（後処理のみ）
- リアルタイム文字起こし（高負荷モード）は `realtime_whisper_model`（既定 `base`）を使用します。後処理（`whisper_model`）とは別モデルで、低遅延優先です

初回実行時にモデル（`large-v3-turbo` で約1.5GB）を HuggingFace からダウンロードします（要インターネット・1回限り）。

## ❓ トラブルシューティング

- **「ffmpeg.exe が見つかりません」** — `ffmpeg.exe` がプロジェクト直下にあるか確認してください。
- **後処理が遅い** — CPU モードでは会議長の数倍の時間がかかります。GPU があれば `whisper_device=cuda` に変更してください。
- **固有名詞が誤認識される** — `glossary.csv` に「正規形」と「別名（誤認識例）」を登録してください。
- **音声デバイスが出ない** — 「🔄 デバイス再検出」ボタンを押すか、録音中でないことを確認してください。
- **モデルのダウンロードで失敗する** — 初回のみネットワーク接続が必要です。再実行で再取得できます。
