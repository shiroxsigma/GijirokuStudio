# GijirokuStudio（議事録スタジオ）

リモート会議を **音声（MP3）＋ 画面スライド（JPEG）＋ 文字起こし** で記録し、話者を分けた **議事録（Markdown / HTML / DOCX）** を生成する Windows 向けデスクトップアプリです。既定ではすべてローカルで動作し、会議音声が外部に送信されることはありません。

---

## ✨ 主な機能

- **リアルタイム MP3 録音** — スピーカー（ループバック）・マイクを複数同時録音し ffmpeg で MP3 エンコード
- **話者分離** — マイク＝自分 / スピーカー＝相手 として役割別トラックを記録し、議事録に「自分 / 相手」を付与（diarization モデル不要）
- **スライド自動キャプチャ** — 5秒ごとに画面変化（dHash）を検知し、切り替わった瞬間だけ JPEG で保存。手動キャプチャも可能
- **キャプチャ範囲の指定** — ドラッグで資料領域だけを切り出し。誤検知が減り、OCR 精度とファイルサイズも改善
- **⭐ マーカー** — 会議中に「今の重要」をワンボタン／グローバルホットキーで記録。議事録でハイライトされ、AI要約でも優先される
- **リアルタイム文字起こし（高負荷モード）** — ローカル AI（faster-whisper）で話しながら文字起こし
- **議事録の自動生成（後処理）** — 高精度文字起こし → スライドOCR → AI要約 → Markdown / HTML / DOCX 出力
- **AI要約** — サマリ・決定事項・アクションアイテム（担当／期限）・未決事項を抽出。Ollama（ローカル完結）または Claude API を選択
- **スライドOCR** — Windows 内蔵の日本語 OCR でスライドの文字を抽出。音声で拾えない数値・固有名詞を補完
- **記録一覧ブラウザ** — 過去の記録を一覧・全文検索し、その場で再後処理
- **用語辞書（glossary.csv）** — 固有名詞の誤認識を正しい表記に寄せる

## 🖥️ 動作環境

- Windows 10 / 11
- Python 3.13
- 同梱の `ffmpeg.exe`（プロジェクト直下に配置済み）
- マイク・スピーカーが利用可能なオーディオ環境

## 📦 セットアップ

```bash
# 1) 仮想環境を作成して依存パッケージをインストール
python -m pipenv --python 3.13     # open_py313.bat と同等
pipenv install                      # Pipfile から一括インストール
```

主な依存パッケージ: `mss`, `pillow`, `imagehash`, `pyaudiowpatch`, `sounddevice`, `numpy`, `scipy`, `faster-whisper`, `moonshine-voice`

任意の追加パッケージ（使う機能に応じて）:

| パッケージ | 必要になる場面 |
|---|---|
| `anthropic` | AI要約で `summary_provider="claude"` を選ぶ場合 |
| `python-docx` | DOCX 出力（`export_docx=true`）を使う場合 |
| `rapidocr-onnxruntime` | OCR のフォールバック。Windows 内蔵 OCR が動く環境では不要（onnxruntime 込みで約100MB） |

## 🎬 使い方

1. **会議名を入力**（省略可。フォルダ名・議事録タイトルに使われます）
2. **対象画面** と **音声デバイス** を選択
   - 対象画面は「全画面」「ディスプレイ指定」に加えて **「範囲を指定（ドラッグ）」** が選べます
   - Ctrl/Shift+クリックで複数選択。**「🎚 すべて選択」** でまとめて選択できます
   - **マイクとスピーカーを両方選ぶと話者分離が有効**になります
3. **動作モード** を選択
   - `軽量（録音のみ）` — 後処理で一括文字起こし
   - `高負荷（リアルタイム文字起こし）` — 録音中に文字起こしを表示
4. **▶ 会議記録を開始**
   - **⭐ マーカー**（既定 `Ctrl+Shift+M`）で重要な瞬間を記録。**他アプリが前面でも効きます**
   - **📷 手動キャプチャ**で任意タイミングのスクリーンショット
5. **■ 記録を停止して保存**
6. **📄 議事録を生成（後処理）** — 進捗バーが表示され、**✖ 中断**でいつでも止められます

過去の記録は **メニュー → 記録 → 記録一覧を開く** から一覧・検索・再後処理できます。

## 🖱 キャプチャ範囲の指定

「対象画面」で **範囲を指定（ドラッグ）** を選ぶと、画面が暗転してドラッグで矩形を選べます。

- ドラッグ中はサイズを表示。**Esc または右クリックでキャンセル**
- 選んだ範囲は `settings.json` に保存され、次回起動時もそのまま使えます
- 録画中は変更できません（開始時の範囲で固定されます）
- ディスプレイ構成が変わって範囲が画面外になった場合は、開始前に確認を出します

資料の領域だけに絞ると副次的な効果があります:

- **dHash が資料だけを見る** — タスクバーの時計や通知トーストで誤検知しなくなり、スライドの小さな変化には敏感になります
- **OCR の精度が上がる** — 文字が画像内で相対的に大きくなるため
- **ファイルと HTML が小さくなる**

画像は長辺が `capture_max_edge`（既定 1600px）を超える場合だけ縮小されます。4K画面の全画面選択でも肥大化しません。

## 🗣️ 話者分離について

マイクとスピーカーを**両方**選択して録音すると、通常の `audio_main.mp3` に加えて役割別のトラックが保存されます。

| ファイル | 内容 |
|---|---|
| `audio_main.mp3` | 全ソースのミックス（再生用・192kbps） |
| `audio_self.mp3` | マイクのみ＝**自分**（文字起こし用・16kHz mono 64kbps） |
| `audio_other.mp3` | スピーカーのみ＝**相手**（同上） |

後処理ではこの2本を別々に文字起こしし、時系列でマージして話者タグを付けます。

> ⚠️ **ヘッドセットの使用を推奨します。** スピーカーから音を出していると、相手の声をマイクが拾って `audio_self.mp3` に混入し、同じ発言が「自分」「相手」の両方に現れることがあります。

## 🤖 AI要約について

設定ダイアログの「AI要約（後処理）」で選択します。既定は **なし**。

| プロバイダ | 動作 | 備考 |
|---|---|---|
| なし | 要約しない | 既定 |
| Ollama | **ローカル完結** | 別途 Ollama の起動が必要。既定モデル `qwen3` |
| Claude API | **文字起こしを外部送信** | `anthropic` パッケージと API キーが必要。既定モデル `claude-opus-5` |

- API キーは環境変数 `ANTHROPIC_API_KEY`、または `settings.json` の `anthropic_api_key`
- 出力は JSON スキーマで固定しているため、レポートへの取り込みが安定します
- **要約に失敗しても議事録の生成は続行します**（要約は付加物という扱い）
- ⭐ マーカーの前後60秒の発言は「重要」として要約に渡されます

## 🔤 スライドOCR について

キャプチャしたスライドから文字を抽出し、議事録に折りたたみで埋め込みます。HTML の全文検索でも引っかかります。

- 既定は **Windows 内蔵 OCR**（`Windows.Media.Ocr`）。追加インストール不要で日本語が正確です
- 日本語 OCR 言語パックが入っていない環境では `rapidocr-onnxruntime` にフォールバックします
  - ただし既定モデルが中国語のため、漢字が簡体字に化けます（売上→壳上、営業→當業）。数値と英字は正確です
- 結果は `ocr.jsonl` にキャッシュされ、再後処理では再実行しません

## ⚙️ 設定（settings.json）

メニュー **設定 → 設定を開く** で主要項目を変更できます。それ以外は `settings.json` を直接編集します。

| キー | デフォルト | 説明 |
|---|---|---|
| `dhash_threshold` | `10` | 画面変化の検知感度（小さいほど敏感） |
| `audio_gain` | `2.0` | 音声の増幅度（1.0〜5.0） |
| `jpeg_quality` | `85` | キャプチャ画像のJPEG画質（50〜100） |
| `capture_region` | `null` | ドラッグで選んだ範囲 `{left,top,width,height}` |
| `capture_max_edge` | `1600` | 画像の長辺上限（px）。`0` で無効 |
| `whisper_model` | `large-v3-turbo` | 後処理の faster-whisper モデル |
| `whisper_device` | `cpu` | `cpu` / `cuda`（NVIDIA GPU） |
| `whisper_compute` | `int8` | CPU=`int8`、CUDA=`float16` など |
| `realtime_whisper_model` | `base` | 高負荷モードのリアルタイム文字起こし用モデル |
| `marker_hotkey` | `ctrl+shift+m` | マーカーのグローバルホットキー |
| `summary_provider` | `none` | `none` / `ollama` / `claude` |
| `summary_model` | （空） | 空なら各プロバイダの既定 |
| `ollama_url` | `http://localhost:11434` | Ollama のエンドポイント |
| `summary_chunk_chars` | `6000` | Ollama の分割サイズ |
| `anthropic_api_key` | （空） | 空なら環境変数 `ANTHROPIC_API_KEY` |
| `ocr_enabled` | `true` | スライドOCRの有効/無効 |
| `ocr_backend` | `auto` | `auto` / `windows` / `rapidocr` |
| `ocr_lang` | `ja` | OCR の言語 |
| `export_html` | `true` | HTML を自動出力 |
| `export_docx` | `false` | DOCX を自動出力（`python-docx` が必要） |
| `html_embed_images` | `true` | 画像を HTML に base64 埋め込み |
| `html_embed_audio` | `false` | 音声も埋め込む（1時間で約37MB増） |

> GPU（CUDA）環境があれば `whisper_device=cuda` / `whisper_compute=float16` にすると、後処理が大幅に高速化します。

## 📖 用語辞書（glossary.csv）

固有名詞・専門用語・人名の誤認識を正しい表記に寄せる辞書です。

```csv
正規形,読み,別名1,別名2
開発定例会議,カイハツテイレカイギ,開発定例会,
プロダクト戦略室,プロダクトセンリャクシツ,プロダクト線略室,プロダクト戦略しつ
山田太郎,ヤマダタロウ,,
```

- **1行 ＝ 1用語**：1列目＝正規形、2列目＝読み、3列目以降＝別名（誤認識されやすい表記）
- **正規形** は faster-whisper の `initial_prompt` に使われ、認識時点で正しい用語に寄ります
- **別名** は後処理で「正規形」へ一括置換されます
- Excel で編集する場合は **CSV (UTF-8)** 形式で保存してください

### 単一HTMLについて

`meeting_report.html` は画像を base64 で埋め込んだ1ファイルです。

- **時刻をクリックするとその位置から音声が再生されます**
- 発言のインクリメンタル検索・ハイライト
- 音声は既定で相対パス参照（`html_embed_audio=true` で埋め込み可）
  - 1時間の 192kbps MP3 は base64 で約115MB になるため、埋め込み時は 64kbps mono に再エンコードします（約37MB）

## ❓ トラブルシューティング

- **「ffmpeg.exe が見つかりません」** — `ffmpeg.exe` がプロジェクト直下にあるか確認してください。
- **音声デバイスを複数選ぶと録音できない／落ちる** — 修正済みです。それでも起きる場合は動作ログの「[スキップ]」「無音（データ未着）」を確認してください。
- **一部のデバイスが「[スキップ]」される** — そのデバイスがドライバ側で開けない状態です（WDM-KS の排他利用など）。他のデバイスで録音は継続されます。
- **「音声が1バイトも記録されませんでした」** — 選択したデバイスがすべて無音／使用不可です。ヘッドセットやスピーカーの選択を見直してください。
- **後処理が遅い** — CPU モードでは会議長の数倍かかります。GPU があれば `whisper_device=cuda` に変更してください。途中で **✖ 中断** できます。
- **マーカーのホットキーが効かない** — 他のアプリが同じ組み合わせを使用しています。動作ログに出るので `settings.json` の `marker_hotkey` を変更してください。
- **OCR が動かない** — Windows の日本語 OCR 言語パックが必要です（設定 → 時刻と言語 → 言語 → 日本語 → オプション → 光学式文字認識）。
- **固有名詞が誤認識される** — `glossary.csv` に「正規形」と「別名（誤認識例）」を登録してください。
- **HTML が重い** — 画像が多い場合は `html_embed_images=false` にすると相対パス参照になります。
