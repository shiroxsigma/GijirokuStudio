## 1. システム概要
本システムは、マシンスペックが制限された環境（Intel Core 5 120U / メモリ16GB）において、リモート会議（Microsoft Teams, Zoom等）の内容をバックグラウンドで高効率かつリソース非圧迫で記録するためのデスクトップアプリケーションである。CPU使用率を極限まで抑えながら、音声の常時録音と、5秒間隔での画面変更検知（dHashアルゴリズム）を行い、リソースの余力状況に応じて文字起こしの実行フェーズを動的に切り替える仕組みを提供する。

### 1.1 実装形態（★変更）
- **GUIアプリケーション**: Python `tkinter` ベースのデスクトップGUI（620×750px、リサイズ不可）
- **CLIモード**: `--post-process FOLDER` 引数によるバッチ処理モード（後処理・Markdown生成用）

## 2. 基本要件及び制約条件

- **音声取得（★大幅変更）**
  `ffmpeg` は音声キャプチャには使用せず、**PCMストリームのMP3エンコード専用**として利用する。音声キャプチャ自体は以下のPythonライブラリで行う：
  - **スピーカー音声**: `pyaudiowpatch` ライブラリを用いて WASAPI ループバックデバイスから直接キャプチャ
  - **マイク音声**: `sounddevice` ライブラリを用いてデフォルト入力デバイスからキャプチャ
  - キャプチャしたPCMデータは `subprocess.PIPE` 経由で ffmpeg に送信し、リアルタイムMP3エンコードを行う（Capturaパターン）

- **音声ソース選択（★新規）**
  GUI上で以下の3種類から音声ソースを選択可能：
  1. スピーカーのみ（ループバック）
  2. マイクのみ
  3. 両方（ミックス）— numpyによるPython内ミキシング

- **ミキシング処理（★変更）**
  ffmpegの`amix`フィルターではなく、Python/numpyによるソフトウェアミキシングを実装。1024フレーム（4096バイト）の固定サイズチャンク単位でスピーカー・マイク双方のバッファから読み出し、float32加算後にクリッピングして出力する。片方のソースが停止・遅延した場合のオーバーフロー対策（~1.2秒バッファ上限）を実装。

- **画面キャプチャ（★変更）**
  対象は「全画面（Virtual Screen）」をデフォルトとするが、**GUI上で各ディスプレイを個別に選択可能**。マルチディスプレイ環境ではプライマリ・セカンダリの個別指定、または仮想画面全体のキャプチャを選べる。不要情報の映り込みは事後手動削除を前提とし、処理の軽量化を最優先とする。

- **キャプチャ間隔**
  5秒に1回（定周期実行）。

- **画像保存形式**
  JPEG形式（画質設定：85%固定）。PNGに比べファイルサイズを大幅に削減し、ディスクI/O負荷を低減する。

- **手動キャプチャ機能（★新規）**
  録音中に「📷 手動キャプチャ」ボタンで任意タイミングのスナップショットを保存可能。自動のdHash検知とは別に、ユーザーが重要な画面を確実に記録できる。

- **入力レベルメーター（★新規）**
  GUI上にリアルタイム音声レベルメーターを表示。80ms間隔で更新し、レベルに応じて色が変化（緑<0.6 / 黄<0.85 / 赤）。表示/非表示をチェックボックスで切り替え可能。

- **省電力・スリープ**
  OS標準のスリープ・画面オフ制御への介入（API呼び出しなど）は不要。ユーザーの既存設定に従う。

## 3. 動作モード仕様
マシンの負荷状況や実行時のGUI設定により、以下の2つのモードを切り替えて動作させる。

### 3.1 低負荷モード（録音のみ）
会議中のCPUプレッシャーを最小化し、ファンノイズや他アプリケーション（Office、ブラウザ等）の動作遅延を防ぐモード。
- **会議中：** 音声のストリーム録音（MP3エンコード・ファイル書き出し）と、5秒間隔の画面dHash比較および変更検知時のJPEG保存のみを実行。文字起こし処理は一切行わない。

### 3.2 高負荷モード（リアルタイム処理型）
会議進行と並行して、テキスト化された議論の内容をリアルタイムに確認するモード。
- **会議中：** 音声を常時録音しつつ、`moonshine-voice` ライブラリを用いてストリーミング文字起こしを非同期で実行。音声PCMデータをトランスクリプションキューに転送し、1秒間隔のバッファを蓄積後にトランスクリーバーへ供給する。画面キャプチャの仕様は低負荷モードと同一。

> **注（旧仕様からの変更点）:**
> - 旧仕様では高負荷モードは「一定秒数ごとに音声ファイルをチャンク分割出力」していたが、実装では**キュー ベースのストリーミング方式**に変更。
> - 旧仕様では低負荷モードの後処理に `whisper.cpp` を想定していたが、CLIの `--post-process` コマンドで `moonshine-voice` のバッチ処理を使用。

## 4. 技術スタック及びコンポーネント選定

| コンポーネント | 選定技術 | 理由・特徴 |
| :--- | :--- | :--- |
| **音声キャプチャ（スピーカー）** | **pyaudiowpatch (Python)** | WASAPI ループバックデバイスに直接アクセス可能なPyAudio拡張。`ffmpeg -f dshow` よりもデバイス制御が正確。 |
| **音声キャプチャ（マイク）** | **sounddevice (Python)** | PortAudioの薄いラッパー。デフォルトマイクの検出・キャプチャがシンプル。 |
| **音声エンコード** | **ffmpeg (CLI)** | stdinから受け取ったPCM (s16le, 44100Hz, stereo) を `libmp3lame` で192kbps MP3にリアルタイムエンコード。キャプチャは行わない。 |
| **PCM正規化・リサンプル** | **NumPy + scipy.signal.resample** | キャプチャ時のチャンネル数/サンプルレート差異をPython内で吸収。ステレオs16le 44100Hzに統一してffmpegに送信。 |
| **画面キャプチャ** | **mss (Python)** | OSのグラフィックAPIを直接呼び出すCバイト互換の軽量ライブラリ。`pyautogui` や `Pillow` よりも高速かつ低CPU負荷。 |
| **差分検知** | **ImageHash (dHash)** | 画像を9x8の極小グレースケールに縮小し、隣接ピクセルの輝度勾配を64bitハッシュ化。計算量がほぼゼロ。閾値=10（固定）。 |
| **文字起こし（リアルタイム）** | **moonshine-voice** | ローカルAIベースの音声認識エンジン。ストリーミングモード対応。 |
| **文字起こし（バッチ後処理）** | **moonshine-voice** | `--post-process` CLIでバッチモード起動。16kHz mono WAVにデコード後、高精度一括文字起こしを実行。 |

> **旧仕様からの変更点:**
> - 音声キャプチャ：`ffmpeg -f dshow` → `pyaudiowpatch` + `sounddevice`
> - ミキシング：`ffmpeg amix フィルター` → `numpy` によるPython内ソフトウェアミキシング
> - 文字起こし：`whisper.cpp / faster-whisper` → `moonshine-voice`
> - 新規：`scipy.signal.resample`（トランスクリプション時のリサンプル）

## 5. 詳細設計及びアルゴリズム

### 5.1 音声キャプチャ・ミキシング・エンコード アーキテクチャ（★大幅変更）

#### 5.1.1 キャプチャ層
- **スピーカー**: `pyaudiowpatch` でWASAPI loopbackデバイスを列挙し、デフォルト出力デバイスに対応するループバックを自動選択。`stream_callback` で非同期にPCMデータを取得し、`_to_stereo_s16le()` で44100Hz stereo s16leに正規化してキューに投入。
- **マイク**: `sounddevice.InputStream` でデフォルト入力デバイスからキャプチャ。同様に`_to_stereo_s16le()`で正規化。

#### 5.1.2 PCM正規化処理
`_to_stereo_s16le()` メソッドで以下を統一：
- モノラル → ステレオ（チャンネル複製）
- 3ch以上 → ステレオ（最初の2チャンネルのみ抽出）
- サンプルレート変換：`numpy.interp` を用いた線形補間による44100Hzへのリサンプル
- int16範囲クリッピング（-32768〜32767）

#### 5.1.3 ミキシング（両方モード時）
`_mixer_loop()` スレッドで以下を処理：
- スピーカーキュー・マイクキューからデータをbytearrayバッファに蓄積
- 1024フレーム（4096バイト）の固定チャンク単位で双方のバッファから読み出し
- float32加算 → int16クリッピング → 出力
- 片方のバッファが溢れた場合（~1.2秒以上）、単独ソースをそのまま出力（オーバーフロー対策）
- 残データは録音終了時にフラッシュ

#### 5.1.4 ffmpegエンコード
stdinからPCMを受け取り、MP3 192kbpsで出力：
```
ffmpeg -f s16le -acodec pcm_s16le -ar 44100 -ac 2 -i - -c:a libmp3lame -b:a 192k -y output.mp3
```

### 5.2 タイマードリフト（累積遅延）排除ロジック
単純な `time.sleep(5)` では、キャプチャ処理やdHash計算に要した時間（約0.01〜0.03秒）が毎回累積し、1時間の会議で数十秒のズレが生じる。これに対処するため、「次回実行すべき絶対時刻（Epoch Time）」を基準に逆算してウェイトをかける、自動補正型タイマーループを実装する。

```python
INTERVAL = 5.0
next_target = time.time() + INTERVAL

while recording_active:
    sleep_time = next_target - time.time()
    if sleep_time > 0:
        time.sleep(sleep_time)
    
    execute_capture_and_diff_proc()
    
    next_target += INTERVAL
```

### 5.3 dHash（Difference Hash）による画面変化判定
5秒ごとに取得したフル解像度の画面イメージに対し、以下のステップで超軽量差分判定を行う。これにより、時計の秒数進みや細かなノイズを無視し、スライドの切り替え等の大規模な変化のみを検出する。

1. キャプチャ画像を 9 × 8 ピクセルに超縮小し、グレースケール（モノクロ）化。
2. 各行の隣接するピクセル（左と右）の輝度を比較し、左が明るければ 1、右が明るければ 0 として64ビットのビット列（ハッシュ値）を生成。
3. 前回保存された画面のハッシュ値 `H_prev` と、今回取得したハッシュ値 `H_curr` のハミング距離（異なるビットの数: `D_H`）を計算。
4. **判定基準：** `D_H` が 閾値 `T`（**GUIスライダーで1〜30の範囲で可変設定、初期値: 10**）より大きい場合のみ「画面変化あり」とみなし、ディスクへ高解像度JPEGとして保存し、基準ハッシュを更新する。変化がない場合は即座にメモリからクリアする。閾値を小さくするほど小さな変化も検知（保存画像増）、大きくするほど大きな変化のみ検知（保存画像減）。録画開始時にスライダーの値が確定し、録画中は変更不可。

## 6. 文字起こし仕様（★大幅変更）

### 6.1 使用エンジン: moonshine-voice
`whisper.cpp` / `faster-whisper` に代わり、`moonshine-voice` ライブラリを採用。

### 6.2 対応言語（★新規）
GUIで以下の4言語から選択可能。**録音中の動的切替にも対応**（トランスクリーバーをホットスワップ）。

| 表示名 | 言語コード |
| :--- | :--- |
| 日本語 | `ja` |
| English | `en` |
| 中文 | `zh` |
| 한국어 | `ko` |

### 6.3 リアルタイム文字起こし（高負荷モード）
- **モデル事前読み込み**: 高負荷モード選択時にバックグラウンドスレッドでモデルをロード。録音開始までに初期化を完了し、開始直後から文字起こしを開始可能。
- **ストリーミング方式**: 音声PCMをトランスクリプションキュー（maxsize=400）に送信。別スレッド `_transcribe_loop()` が1秒間隔（44100Hz × 2ch × 1秒分）のバッファを蓄積し、モノラル化後に `scipy.signal.resample` で16kHzにダウンサンプル。`ctypes.c_float` 配列としてトランスクリーバーの `add_audio()` に供給。
- **イベント駆動出力**: `LineCompleted` イベントをリッスンし、テキストが確定するたびにGUIの文字起こしエリアに表示。同時に `transcription.txt` ファイルに経過時間付きで追記（`[123.4s] テキスト...`）。

### 6.4 バッチ後処理
2つの実行経路をサポート：

#### CLIモード
`--post-process FOLDER` 引数で指定フォルダの録音データを一括処理：
1. ffmpegで音声ファイルを16kHz mono WAVにデコード
2. `moonshine_voice.Transcriber.transcribe_without_streaming()` で一括文字起こし
3. 各行の `start_time` とスナップショット画像のタイムスタンプを時系列でマージ
4. `meeting_report.md` を自動生成（会議情報、文字起こしテキスト、画面キャプチャ画像を統合）

#### GUIモード（★新規）
GUI上の「📄 議事録を生成（後処理）」ボタンから実行可能。**常に有効**で、録画前後を問わず任意の過去の会議フォルダを指定して議事録生成ができる。
- ボタン押下 → フォルダ選択ダイアログ表示（初期ディレクトリ=直近の録画フォルダ）
- フォルダ選択後 → バックグラウンドスレッドで `post_process_folder()` を実行
- 実行中はボタンが「⏳ 処理中...」に変化しdisabled、stdout出力を動作ログにリアルタイム表示
- 完了後 → ボタンが元に戻り、`meeting_report.md` の生成有無で成功/失敗をログに表示

## 7. 成果物およびファイル管理仕様
すべてのデータは会議ごとの専用ディレクトリ（`YYYYMMDD_HHMMSS_Meeting`）内に格納され、絶対時間タイムスタンプによって一元管理される。

### 7.1 ファイル命名規則

| 種別 | ファイル名 | 備考 |
| :--- | :--- | :--- |
| 音声ファイル | `audio_main.mp3` | 192kbps MP3（旧仕様のWAV/MP3選択からMP3固定に変更） |
| 自動スナップショット | `snapshot_HHMMSS_mmm.jpg` | ミリ秒付き（例：`snapshot_130520_123.jpg` → 13:05:20.123） |
| 手動スナップショット | `manual_HHMMSS_mmm.jpg` | ★新規。手動キャプチャボタンで保存 |
| 会議メタデータ | `metadata.txt` | 構造化キーバリュー形式（後述） |
| 文字起こしファイル | `transcription.txt` | 高負荷モード時のみ。経過時間付きテキスト |
| 議事録Markdown | `meeting_report.md` | ★新規。`--post-process` CLIで生成 |

### 7.2 メタデータ形式（★変更）
`metadata.txt` は以下の構造化キーバリュー形式：

```
START_TIME_EPOCH=1748300000.123
START_TIME_STR=2026-05-28 10:00:00
AUDIO_SOURCE=speaker_loopback|microphone|both_mixed
MODE=light|full
SNAPSHOT_COUNT=42
AUDIO_FILE=audio_main.mp3
TRANSCRIPTION_FILE=transcription.txt   ← 高負荷モード時のみ
```

> **タイムスタンプ紐付けの考え方：**
> 文字起こしテキストが検知した会議開始からの経過秒数を `S_rel`、メタデータに記録された会議開始絶対時刻を `T_start` とすると、紐付けるべきスナップショットの絶対時刻 `T_target` は以下のシンプルな計算で一意に定まります。
> 
> **`T_target` = `T_start` + `S_rel`**
> 
> これにより、後処理のバッチフェーズにおいて、発言内容の経過時間とスナップショット画像のタイムスタンプを完全に同期させたMarkdown形式の議事録を自動生成することが可能となります。

- 議事録生成中: 「ステータス: 議事録生成中...」（黄色）

### 8.8 非同期終了処理
録音停止時、UIは即座に反応し、バックグラウンドスレッドで以下を実行：
1. 全オーディオキャプチャスレッド停止（3秒タイムアウト）
2. ffmpeg stdinクローズ → MP3エンコード完了待ち（10秒タイムアウト）
3. トランスクリーバー停止・クローズ
4. metadata.txt書き出し
5. 完了メッセージボックス表示 → UIリセット
